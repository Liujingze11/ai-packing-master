# AI_PackingEngine 桌面演示版 — 设计文档

日期：2026-11-11
状态：待批准

## 意图与背景

把旧的 Flask+HTML 装箱推荐网页（SmartPackingEngine）改造成**桌面演示程序**，效果优先、能惊艳演示为准。此次开发与仓库隐私清理（历史重写 + 换 noreply 邮箱 + force push）捆绑：开发完成后再一次性重写历史并上传。

旧版功能回忆：输入「零件号 + 数量」→ 查三张 CSV（零件尺寸/箱型/历史方案）→ 体积+承重过滤箱型（留 20% 冗余）→ 调 DeepSeek 给出推荐箱型和装箱策略（纯文本）。

## 目标

1. **输入区**：零件号 + 数量输入，完善校验（正整数、零件号存在性、友好错误提示）
2. **AI 推荐**：调 DeepSeek（OpenAI 兼容接口），输出**结构化 JSON**（推荐箱型 / 推荐理由 / 装箱方案：每箱数量、总箱数、策略建议）
3. **结果卡片**：推荐箱型 / 理由 / 装箱方案分卡展示，不再是糊成一团的文字
4. **3D 装箱模拟**（核心亮点）：Three.js（React Three Fiber）渲染——半透明箱体 + 长方体零件按**确定性网格布局**（fit_l × fit_w × fit_h）逐个飞入动画，OrbitControls 旋转缩放。**播放式**，不做交互拖拽
5. **设置面板**：DeepSeek API key、API base、模型名、冗余系数（默认 0.8）持久化到本地，绝不进 git
6. **数据**：内置示例 CSV 三件套（开箱即跑），支持导入自定义 CSV 三件套
7. 开发模式 `npm run dev` 即起 Electron 窗口（Linux）

## 非目标

- 打包 / 分发（electron-builder 等，后续再说）
- 交互式拖拽 / 手动重排零件
- 服务端、多用户、多端
- Python（纯 TS 一体，不保留 Flask 后端）
- 工业级 3D 装箱求解器（网格布局够演示用）

## 反目标

- 动画再炫也不能卡顿（数据量小，必须流畅）
- 不让 LLM 输出几何坐标（布局由算法精确计算，AI 只出策略）
- 不堆重型状态管理/组件库（demo 用不上的都不引）

## 约束

- 技术栈与本机既有项目一致：**Electron + React 19 + TypeScript + Vite**（参照 mobi-agent-pet 的纯 TS 一体模式、SIA_Agent 的工程结构）
- 3D：Three.js + React Three Fiber
- 中文 UI
- API key 等敏感配置只存本机，且要防再次进 git（.env 进 .gitignore，或 electron-store）

## 与搭档（用户）敲定的决定

| 决定 | 结论 |
|---|---|
| 桌面形态 | Electron + React + TS 一体（纯 TS，无 Python）✅ 用户拍板 |
| 3D 模拟 | 播放式展示，不做交互 ✅ 用户拍板 |
| 3D 技术 | Three.js（R3F 封装）✅ 用户认可 |
| 打包 | 暂不打包，先开发 ✅ 用户拍板 |
| 效果基调 | demo 效果优先，怎么好看怎么来 ✅ 用户拍板 |
| 数据 | 内置示例 CSV + 可导入自定义（默认，用户未反对） |

## 留给实现者决定

- CSV 解析方式（papaparse 或手写，量小）
- 状态管理（useState/useReducer 足够，不引 Redux）
- 3D 配色 / 光照 / 飞入动画曲线与节奏（以流畅惊艳为准）
- 目录结构（参照 SIA_Agent：desktop / shared / tools 分层）
- AI JSON 输出的具体 schema 字段名
- 测试范围：demo 优先；核心计算（容量/布局）给单测，UI 不强求

## 应用流程（供参考）

```
启动 Electron 窗口
  ├─ 顶栏：标题 + 设置入口
  ├─ 左侧：输入区（零件号、数量）→ [开始推荐]
  ├─ 右侧：3D 装箱模拟画布（OrbitControls）
  └─ 底部：结果卡片（推荐箱型 / 理由 / 装箱方案）

推荐流程（主进程或渲染进程内）：
  校验输入 → 读 CSV 三件套 → 体积+承重过滤箱型（×冗余系数）
  → 构造 prompt（候选箱型 + 历史方案）→ LLM 返回 JSON
  → 由选中箱型 + 零件尺寸计算网格布局坐标
  → 3D 场景动画播放
```
