# AI 装箱引擎 v2 — 外卖式混装交互 设计文档

日期：2026-11-12
状态：待批准
取代：v1 布局部分（`2026-11-11-packing-desktop-demo-design.md` 的输入区/结果卡片交互），核心计算与技术栈沿用 v1

## 意图与背景

用户对 v1 试用后的核心反馈：交互界面不好。v2 把交互重构成「**点外卖**」心智模型——说白了就是往箱子里装货：左侧像外卖菜单一样"点"零件进订单，右侧管理/选择箱子，AI 对话区一键开工，3D 主视觉演混装过程。**只做混装场景**（多种零件装进同一个箱子）。

## 目标

1. **左侧：菜单 + 购物车（外卖式）**
   - 零件目录像外卖菜单：每个零件一张"菜品"卡（名称、尺寸、重量），带「+」按钮
   - 点「+」加入订单（购物车），订单区显示「零件 × 数量」，可加减、可删除
   - 零件可**逐个录入**（名称/长宽高/重量/材质）并持久保存；**不预填任何零件**（通用性）
2. **右侧：箱子管理**
   - 已保存箱型列表，点选当前要用的箱子（单选）
   - 新建箱子：输入名称 + 长宽高（+ 最大承重，可选）→ 保存，重启仍在
3. **AI 对话区**
   - 购物车有货 → 发送键自动点亮（无货置灰）
   - 发送内容 = 当前订单 + 选中箱子 + 用户留言（可选，如「易碎需缓冲」）
   - AI 回复出现在对话区（推荐理由 / 装箱策略 / 每箱方案 / 总箱数），3D 同步播放
   - 连续发送 = 按当前订单与留言重新计算（每轮独立，不带对话记忆）
4. **混装算法（唯一场景）**
   - 订单含多种零件（SKU × 数量），混装进同一箱子
   - 提案：按体积降序排 SKU → 每个 SKU 独占若干水平层（层内按该 SKU 网格摆放）→ 逐层叠放到箱高上限 → 单箱各 SKU 装入量确定 → 循环装箱直至订单完成，得总箱数；全程校验体积与承重
5. **3D 主视觉**：混装过程逐层飞入，**每种零件一种颜色**，层序清晰；徽标「共需 N 箱 · 本箱混装 X 种」；可旋转缩放重播
6. 设置面板沿用（key/base/model/冗余系数/mock），默认 mock 可离线演示

## 非目标

- 分箱场景（每种零件各自装箱）——明确不做
- 多轮对话记忆（每轮独立重算）
- 打包分发（后续再说）
- 云端/多用户

## 反目标

- 3D 不允许退居次要（主视觉地位）
- 不硬编码零件/箱型（通用系统，目录全由用户数据驱动）
- 不引入重型状态管理/组件库

## 约束

- 技术栈不变：Electron + React 19 + TS + Vite + Three.js（R3F）
- 零件/箱型目录、设置均持久化到 userData（JSON）；内置示例数据仅作可选种子（首次启动提供「载入示例数据」入口，不自动注入）
- 现有可复用：csv 解析、packing 计算（扩展为混装）、llm 层（prompt 改为订单语义）、settings、3D 场景（扩展多色分层）

## 与搭档敲定的决定

| 决定 | 结论 |
|---|---|
| 交互模型 | 外卖式菜单+购物车 ✅ 用户提出 |
| 场景 | **只做混装** ✅ 用户拍板 |
| 箱子 | 右侧管理：选择 + 自定义（长宽高命名保存）✅ 用户提出 |
| 零件 | 逐个添加保存，不预填，保持通用 ✅ 用户提出 |
| AI 入口 | 对话区发送，有货点亮 ✅ 用户提出 |
| 3D | 保持主视觉 ✅ |

## 提案的混装算法（留给实现者细化）

- SKU 排序：体积降序（大件垫底）
- 每 SKU 分层：层内网格 `floor(内长/件长)×floor(内宽/件宽)`，每层件数固定
- 层叠至箱高或承重上限；层高按 SKU 件高
- 单箱模拟装入各 SKU 数量 → 循环得总箱数
- AI 只输出策略文本（隔板/缓冲/顺序建议），几何数字一律算法产出
